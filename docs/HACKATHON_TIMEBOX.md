# HACKATHON_TIMEBOX — дедлайны и режим риска

## Официальная программа Ростовского этапа

Источник: `https://космохакатон.рф/rostov/`

На опубликованной программе этап проходит **4–6 сентября 2026 года** (время местное для площадки).

Критические точки:

- пятница: после презентации кейсов начинается разработка;
- суббота 11:30 — чек-поинт №2;
- **суббота 23:30 — СТОП-КОД / дедлайн загрузки решений**;
- после СТОП-КОД допускается доработка презентации согласно опубликованной программе;
- **воскресенье 10:00 — сдача презентаций**;
- далее — защиты.

## Rule

Если среда имеет доступ к текущему времени, перед крупной задачей оцени оставшееся время до СТОП-КОД.

### До stop-code, много времени

Можно делать high-impact feature work при контролируемом риске.

### Близко к stop-code

Снижать риск:

1. critical bugs;
2. Case Fit;
3. demo flow;
4. DZZ clarity;
5. visible polish;
6. regression tests;
7. reset/demo reliability;
8. только затем новые функции.

### После официального stop-code

**Не изменять код, если правила этапа запрещают доработку после СТОП-КОД.**

Не пытаться обходить дедлайн. Переключиться только на действия, которые официально разрешены после stop-code (например, доработка презентации, если она разрешена правилами), либо на анализ без внесения изменений.

Если есть более свежая официальная инструкция организаторов/платформы — она имеет приоритет над этим файлом.

## Unknown judging criteria

Публичная страница говорит о единых критериях/общем зачёте, но этот файл не выдумывает детальную шкалу жюри. Если платформа, документы кейса или организаторы дают конкретные критерии, Research/Case Agent должен зафиксировать их и скорректировать `QUALITY_SCORECARD.md`/`HACKATHON_STRATEGY.md`.
