# DEMO_FLOW — эталон демонстрационного пути

Это живой документ. Он должен описывать **фактический лучший путь**, а не мечту, которой нет в приложении.

## Текущая целевая гипотеза

1. **Hook / Space**  
   Короткий wow-старт: Земля/спутниковый контекст → переход к побережью.

2. **Coast reveal**  
   Игровая карта побережья. За несколько секунд понятно, где мы и что это экологический мир.

3. **Mission onboarding**  
   NPC/система сообщает: обнаружен подозрительный участок побережья; нужно разобраться.

4. **Problem discovery**  
   Проблемная зона визуально различима, но не настолько очевидна, что анализ становится бессмысленным.

5. **DZZ / observation interface**  
   Пользователь открывает слой/сканер и видит, что решение основано на наблюдении территории.

6. **Interpretation**  
   Короткое действие или выбор заставляет понять данные, а не просто прочитать готовый ответ.

7. **Decision**  
   Пользователь выбирает действие/приоритет, логически связанный с наблюдаемой проблемой.

8. **Consequence**  
   Мир визуально меняется: загрязнённый участок → очищенный/улучшенный; прогресс/XP/impact feedback.

9. **Educational payoff**  
   Одна короткая мысль связывает игровой опыт с реальным «Чистым берегом», ДЗЗ и образовательным проектом.

10. **Continuation**  
    Понятный намёк на более широкий мир/обучение/новые территории без необходимости строить огромный продукт.

## Demo acceptance

Главный путь должен:

- работать с чистого состояния;
- не требовать debug panel;
- не иметь dead ends;
- не заставлять презентующего объяснять, куда нажать;
- не зависеть от случайности;
- быть повторяемым;
- иметь безопасный reset для повторной защиты;
- нормально проходиться на основном мобильном viewport;
- не иметь долгих необязательных ожиданий.

## Pacing questions

При каждом полном проходе измерять/оценивать:

- через сколько секунд пользователь понимает тему;
- через сколько секунд видит ДЗЗ;
- сколько кликов до главной фишки;
- есть ли сцены, где ничего содержательного не происходит;
- не перекрывает ли анимация понимание;
- возникает ли «вау» до того, как внимание потеряно;
- достаточно ли силён финальный payoff.

## Demo mode

Debug tools допустимы для разработки, но основной demo должен работать без них. Допустим отдельный безопасный `Reset demo`, если он не портит пользовательский интерфейс и скрыт/уместно размещён.
